SUMMARY

사무동은 정상 가동 중입니다. 이번 보고는 두 가지를 다룹니다 — 클로드 코드를 운영하는 방법과, 사업·업무 방향에 대한 제언입니다. 아직 도구가 손에 익지 않은 것은 자연스러운 과정이니 조급해할 필요는 없습니다.

SECTION A

클로드 코드 운영 가이드

planner읽기 전용 · 계획 수립
coder범위 내 구현
tester실행·검증
reviewer읽기 전용 · 리뷰
오케스트레이션
/orchestrate 한 마디로 위 4개 역할을 순서대로 지휘합니다. 다만 간단한 작업까지 매번 부르면 오히려 번거로우니, 조사가 길거나 단계가 많은 일에만 사용합니다.
상시 커맨드
/commit·/catchup·/todos·/code-review·/pr-description — 매번 새로 설명하지 않아도 되는 정해진 규칙입니다. 하루에 하나씩 익히는 편이 열 개를 한 번에 배우는 것보다 낫습니다.
Plan 모드
규모가 큰 작업 전에는 계획 모드로 먼저 그림을 맞춥니다. 계획 없이 바로 구현을 시키면 의도와 다른 방향으로 진행될 수 있습니다.
메모리
한 번 말해준 선호와 교훈은 다음에도 그대로 재사용합니다. 잘못 기억한 내용이 있으면 즉시 정정을 요청하는 편이 좋습니다.
되돌리기 힘든 명령
reset --hard, force push, 파일 전체 삭제 같은 명령은 한 번 실행하면 되돌릴 수 없습니다. 커밋·푸시는 항상 최종 확인 후 진행합니다.
훅(Hooks)
반복 작업을 자동화하지만, 규칙을 잘못 만들면 그 실수도 그대로 반복됩니다. 신중하게 설계합니다.
CLAUDE.md
현재 비어 있습니다. 프로젝트 개요·구조·명령어를 채워두면 이후 작업 속도와 정확도가 눈에 띄게 개선됩니다.
SECTION B

사업·업무 방향 메모

재주와 실행
코드를 잘 짓는 것과 그것으로 무언가를 세우는 것은 서로 다른 역량입니다. 하나를 잘한다고 다른 하나가 저절로 따라오지 않습니다.
작업 방식 자체가 자산
계획→구현→검증→재확인의 흐름, 세 번 확인하는 습관, 새 도구 도입 전 허락을 구하는 규칙 — 지금 혼자 쓰는 이 방식을 다듬어 정리해두면 그 자체가 나중에 보여줄 수 있는 자산이 됩니다.
작게 시작
완벽하게 갖추고 시작하기보다 작은 단위로 먼저 내놓고 반응을 봅니다. 기능 열 개짜리 큰 상품보다 하나를 확실히 풀어주는 작은 도구가 먼저 신뢰를 얻습니다.
최종 판단은 직접
일을 나눠주는 것과 책임까지 넘기는 것은 다릅니다. 편해질수록 사람·자금·신뢰에 대한 마지막 판단은 더 꽉 잡고 있어야 합니다.
검증 습관
좋은 소식일수록 한 번 더 확인합니다. 나쁜 소식은 스스로 드러나지만, 달콤한 말은 확인하지 않으면 나중에 크게 터집니다.
속도 조절
하루에 하나씩 익히고 몸에 붙이면 다음으로 넘어갑니다. 일하는 만큼 쉬는 시간도 정해두고, 혼자 다 하려 하지 않습니다.
신뢰의 복리
재주로 얻은 기회는 한 번뿐이지만, 신뢰로 쌓은 관계는 계속 다시 찾아옵니다.
방향 선택
당장의 이익과 오래 자랑스러울 가치가 갈릴 때는 후자를 택합니다. 남는 시간은 잡무가 아니라 사람과 방향을 고민하는 데 씁니다.
