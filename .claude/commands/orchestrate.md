---
description: 사용자 요청을 받아 planner → coder → tester → reviewer 서브에이전트를 순서대로 지휘해 처리
---

사용자가 요청한 작업 "$ARGUMENTS"을(를) 아래 파이프라인으로 처리해줘. 너(메인 에이전트)는 각 단계를 지휘하고 결과를 검증하는 오케스트레이터 역할이야.

1. **planner** 서브에이전트를 호출해서 작업을 구체적인 단계별 계획으로 쪼개. 계획에 열린 질문이나 애매한 부분이 있으면, 넘어가기 전에 사용자에게 확인해.
2. 계획의 각 단계에 대해 **coder** 서브에이전트를 호출해서 해당 단계만 좁게 구현시켜. 한 번에 여러 단계를 몰아서 시키지 마.
3. 각 구현 단계가 끝나면 **tester** 서브에이전트를 호출해서 실제로 동작하는지 검증시켜. PASS/FAIL과 근거(실행한 명령, 출력)를 반드시 받아.
   - FAIL이면 실패 내용을 **coder**에게 그대로 전달해서 고치게 하고, 다시 **tester**로 재검증. 같은 문제가 반복되면 원인 분석이 필요하다는 뜻이니 `debugger` 서브에이전트로 전환해.
4. 전체 구현이 PASS되면 **reviewer** 서브에이전트를 호출해서 정확성/중복/효율성 관점으로 최종 리뷰시켜. 리뷰에서 나온 지적사항 중 반영할 건 **coder**에게 다시 보내 수정 → **tester**로 재검증.
5. 모든 단계가 끝나면 사용자에게 요약을 보고해: 무엇을 구현했는지, 어떻게 검증했는지, 리뷰에서 나온 이슈와 처리 여부. 이 과정에서 커밋/푸시 같은 되돌리기 어려운 작업은 사용자 확인 없이 하지 마.
